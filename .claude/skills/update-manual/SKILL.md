# 📘 設定マニュアルを、今の画面に合わせ直す

このアプリの利用者向けマニュアルは **1本だけ**あります。

| もの | 場所 |
|---|---|
| マニュアル本体（正本） | `docs/エンカンAI_設定マニュアル.html` |
| 項目の記録（前回直したときの状態） | `docs/manual_items.json` |
| 見比べる道具 | `tools/manual_check.py` |
| 公開ページ（Artifact） | https://claude.ai/code/artifact/f2c337fe-49c8-45a1-920f-eb8ceb30a5d1 |

⚠️ **新しいマニュアルを作らないこと。** 上のファイルとURLを更新する。
別に作ると、担当者が古いほうを見続けることになる。

## 手順

### 1. どこが変わったかを出す

```bash
python tools/manual_check.py --check
```

何も出なければ、画面の入力欄は変わっていない。
それでも文言の直しを頼まれているなら 2 へ進む。

「増えた／消えた」が出たら、そのファイル名と項目名を控える。
`種類｜ラベル` の形で出る（例：`text_input｜パターンの名前`、`列｜目印`）。

### 2. マニュアル本体を直す

`docs/エンカンAI_設定マニュアル.html` を編集する。

- 章立ては**タブの並び順**（00 はじめに 〜 10 付録）。新しい項目は、その項目が
  出てくるタブの章の、**画面と同じ位置**に入れる。
- 表は必ず **「項目 / 何を決める / どう設定する」の3列**。この形をくずさない。
- 書くのは**画面に出ている文言のまま**。コードの変数名（`auto_send` など）は書かない。
  読む人は非エンジニアの担当者。
- 既定値（既定ON／既定OFF）と、**間違えたときに何が起きるか**を必ず書く。
  とくに取り消せない操作（SMS一括送信・Salesforce投入・キャリア申請）は
  `.stop` の赤枠で、止め方とセットで書く。
- 増えた項目が「どう設定するか」まで読み取れないときは、
  その画面のコード（`help=` や `st.caption`）を読んでから書く。推測で書かない。

⚠️ HTMLは `<!doctype>` / `<html>` / `<head>` / `<body>` を持たない形で書いてある
（Artifactに publish するときに包まれるため）。この形をくずさない。

### 3. 記録を更新する

```bash
python tools/manual_check.py --save
```

**マニュアルを直したあとにだけ**実行する。先に走らせると、直していないのに
「ずれなし」になってしまう。

### 4. 公開ページを、同じURLに publish し直す

Artifact ツールを、**上の URL を `url` に渡して**呼ぶ。
`url` を渡さないと、別のページが新しく作られてしまう（担当者に配ったリンクが古いままになる）。

publish の前に `action: "read"` でその URL を読み、返ってきた版の上に直しを重ねる。

### 5. コミットする

`docs/エンカンAI_設定マニュアル.html` と `docs/manual_items.json` は**セットで**コミットする。
片方だけだと、次に `--check` したときに嘘のずれが出る。

コミット名義は `Claude`（`CLAUDE.md` の最重要ルール）。
作業ブランチは `claude/...`。`main` へ直接プッシュしない。

## 別のPCで作業するとき

このファイルも `docs/` も `tools/` も**リポジトリに入っている**ので、
`git pull` すればどのPCでも同じように使える。
公開ページのURLも上に書いてあるので、別のPCからでも同じページを更新できる。
（Claude Codeの「記憶」はPCごとに別なので、URLはそこに置かず、必ずここに書いておく。）
