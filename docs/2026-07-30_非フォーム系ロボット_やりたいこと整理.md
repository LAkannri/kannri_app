## 1. 大分岐：ロボットの2タイプ

| タイプ | 動き | 単位 |
|---|---|---|
| **フォーム系** | 最終シートを1行ずつ読む → 各セルを画面の各欄に入力 → 1件ずつ申請 | **セル単位・行ループ・項目マッピングあり** |
| **非フォーム系（CSV/Excel/コピペ/ガス）** | 最終シートを**丸ごと1枚**として扱い、そのまま納品 | **シート丸ごとが単位。セル操作なし** |

- カラム作成（最終シート）は**両タイプとも既存機能で作る**（アプリに入っている）。
- 非フォーム系の「最終シート」が**届ける材料**。そこから先の“届け方”がキャリアごとにバラバラ、というのが今日の主題。

## 3. GASジョブ連携 ＝ 今日追加した器（第1層）

司令室（非フォーム型のみ）に「⚙️ GASジョブ連携」セクションを追加。`config_json["gas_job"]` に保存。

### やりたいこと（一覧・ON/OFF・時刻変更・今すぐ実行・前回成否・エントリーチェック）

- 生成GASは**スプシに置いたまま**（アプリには生成ロジックを持たせない）。
- アプリの役割＝**実行タイミングの管理＋成否の可視化**。

### 実現方式（第1層：OAuth不要・イチオシ）

1. スプシのGASを**ウェブアプリ（`doPost`）としてデプロイ** → 固定URL。`?job=RPG` 等で各キャリア関数へ振り分け。URL悪用防止に**合言葉トークン**。
2. アプリが決めた時刻にURLを叩く → **タイミングはアプリが持つ**ので ON/OFF・時刻変更・今すぐ実行が全部アプリ側で完結。
3. GASは実行結果（成功/失敗・件数・**エントリー出来たかチェック**）を「実行ログ」シートかSupabaseに書く → アプリが読んで**前回の成否表示**。

> 補足：Apps Script標準の時限トリガーは外部から増減しにくいので、**トリガーはGASに置かず“アプリが時刻を持って叩く”方式**にするのがコツ。

### 今日入れた器の中身

- ON/OFF・GASウェブアプリURL・合言葉トークン・実行時刻・実行曜日 → 保存できる。
- 「今すぐ実行」「前回の成否を見る」ボタンは**準備中（disabled）**。実行・成否表示は後日。

## 4. アプリからGASコードを追加/編集（第2層）＝ 後日判断

- 「同じスプシに `.gs` をキャリアごとに追加」をアプリからやる構想（コピペ会社ができた時に作る等）。
- ⚠️ これは **Apps Script API（`projects.updateContent`）が必須 → ユーザーOAuthが必須**。
  - **サービスアカウント（ロボのメアド）は Apps Script API 非対応。**
  - 一度きりのGoogle OAuth設定（Cloudプロジェクト＋同意＋リフレッシュトークン保存）が要る＝唯一の“重い”部分。
- 巻き戻し（過去GASへ復元）も、直接方式なら「保存した旧版をPUTで書き戻す」で自動。
- **進め方の推奨：まず第1層（管理＋成否チェック）を作り、第2層（コード追加）はOAuthをやる覚悟が決まってから。**

## 5. GAS実行の権限まわり（今日確認した重要事実）

- **GASは「実行する人間のGoogleアカウント」の権限で動く**（サービスアカウントではない）。
- 他社スプシのB列にチェック（`setValue(true)`）を書くには、**その実行アカウントが各社スプシに「編集者」で共有**されていればOK。
  - 弊社アカウントは既に各社スプシの編集者に入っている → 自分で実行/自分のトリガーなら成立。
  - 読み取りは閲覧者でOK、**書き込み（チェック）は編集者が必須**。
- ⚠️ もし将来「編集者に入れられない他社スプシ」が出たら、チェックが付かず**BOXに二重集約**が起きうる。その時はB列チェックの代わりに**BOX側で重複キー（顧客ID等）弾き**に切替。
