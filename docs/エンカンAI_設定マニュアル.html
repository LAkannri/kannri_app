① 接続キー（.streamlit/secrets.toml）

キー何のため入れかた・注意
SUPABASE_URL必須ロボットの設定・各タブの設定を貯める場所Supabaseの管理画面からコピー。「⚙️ その他設定」の先頭で ✅ になっていれば読めています。
SUPABASE_KEY必須同上（anon key）同上。
GEMINI_API_KEY録画に必要録画したコードから日本語の手順書を作るAI手順書づくりだけに使います。実行では使いません。
GOOGLE_SERVICE_ACCOUNT_JSONほぼ必須スプレッドシートを読む／書き戻すJSONキーをまるごと貼ります。このアドレスを、使うスプシに共有してください（読むだけなら閲覧者、書き戻すなら編集者）。

GOOGLE_OAUTH_CLIENT_JSONGASを使うなら必須アプリがスプシのGASにコードを書き込んで公開するふつうは、このファイルに書きません。アプリの画面（SMS送信／データローダーの設定）にJSONを貼って保存すれば、Supabaseに入って全員のPCで使えます（＝担当者ごとに secrets.toml を書き替えてもらう必要はありません）。ここに書いた場合は、そちらが優先されます。アプリ全体で1つで足ります（スプレッドシートごとにも、パターンごとにも作りません）。そのCloudプロジェクトで Apps Script API を有効にし、スプシの持ち主のアカウントで script.google.com/home/usersettings の Apps Script API もオンにしてください。
SLACK_WEBHOOK_URLふつうは書きません完了・失敗・確認待ちの通知の送り先このファイルには書かず、「⚙️ その他設定」の「🔔 Slack通知の送り先」で1回保存してください。暗号化してSupabaseに入り、全員のPCで使えます（PCごとに入れる必要はありません）。ここに書いた場合は、そのPCだけこちらが優先されます。

🗃 投入する（投入セット）entry_loader.py

エントリーが終わった案件に「エントリー済み」を書き戻す画面です。こちらもスプシをまたいで1セットにまとめられます。更新と同じく、ホームのタブから開くとそのタブのセットだけが出ます。

項目何を決めるどう設定する
名前 ／ メモこの投入セットの呼び名一覧に出ます。
見出し1件ごとこの投入の表示名例「ドコモ光 エントリー済み」。
URL1件ごと読むスプレッドシート投入元のスプシ。
シートSalesforceへ送る行があるシートURLを入れるとプルダウンになります。
オブジェクト投入先（ふつうは案件＝Opportunity）Salesforceから取ってきた実物の一覧から選びます。
照合キーどの項目で突き合わせるかId＝既存の更新だけ。回線登録番号などの外部ID＝無ければ新規作成。
空欄はSalesforceの値を消す空いているセルの扱い既定OFF＝空欄の列は触りません（Salesforceの今の値が残ります）。ONにすると、Data Loader を手で動かしたときと同じで、空欄の列はその項目を空にします。⚠️ 投入ごとに決めます。「届かなかった項目は触らない」が前提の投入（進捗反映など）でONにすると、正しい値まで消えます。マッピングに書いた列だけが対象です。
すでに違う値が入っている行は送らない（一覧に出す）Salesforceにもともと入っている値を上書きしてよいか既定ON。送る前にSalesforceの今の値を読み、空・同じ値なら入れます。違う値が入っている項目が1つでもある案件は、その案件ごと送らず、結果に「⚠️ すでに違う値が入っていた◯件は送っていません（項目・ID）」と出します（取り込みファイル / 上書きしなかった / に、いまの値と送ろうとした値のCSVも残ります）。見て直してから、もう一度入れてください。付箋・進捗反映のように「空の所に入れる」投入はONのままにします。案内不要落とし・エントリー済みの書き戻し・SMSの送信記録のように上書きが仕事の投入だけ外します（外すと、今までどおり上書きします）。Salesforceの今の値を読めなかったときは、送らずに止まります。
✏️ ただし、Salesforceのこの項目が… ／ …この値なら上書きしてよい任意「違う値は上書きしない」の例外既定は使わない。上の「すでに違う値が入っている行は送らない」がONのときだけ出ます。Salesforceのその案件の項目が選んだ値なら、違う値が入っていても上書きします。項目の一覧には、ふだんはこの投入のマッピングにある項目だけが出ます（ほかの項目を使うときは「マッピングにない項目からも選ぶ」にチェック）。例：付箋の投入で「L-付箋：チェック」が「完了」なら、付箋を付け直してよい。選択リストの項目は値を選び、それ以外は値を「／」で区切って書きます。上書きした件数は結果に「✏️ 上書きしてよい条件に合った◯件は、違う値でも上書きしました」と出ます。条件に合わない案件は、これまでどおり送りません。
🚫 ただし、Salesforceのこの項目が… ／ …この値なら上書きしない任意「上書きしてよい」の例外既定は使わない。すぐ上の「✏️ …この値なら上書きしてよい」を決めたときだけ出ます。上の条件に合っても、Salesforceのその案件の項目が選んだ値なら、上書きせずに送りません（これまでどおり「⚠️ すでに違う値が入っていた」に出ます）。例：付箋の投入で「L-付箋：チェック」が「完了」でも、「L-付箋：内容」が「出電_催促」の付箋は付け直さない。値の選び方・書き方は上と同じです。
マッピングスプシの列 → Salesforceの項目いま使っている .sdl をそのまま取り込めます。書いた列だけが送られ、空のセルはその項目ごと送りません（今の値が残ります）。
  • A🩺 シートと照らし合わせる（送りません）
  • B🧪 お試し（先頭N件）
  • !🚀 全件投入（チェックを入れないと押せません）
全件投入は取り消せません。送る前に「シートに列があるか」「Salesforceに項目があるか」を必ず確かめ、欠けていたら送らずに止まります。

🛡 暮らし安心のエントリーkurashi_ui.py

暮らし安心は、スプシの行ではなく決済システム（登録者管理ボード）が元です。ホームの「🛡 暮らし安心のエントリー」→「🛡 開く」から入ります。

  • 1決済システムからCSVを受け取る（未エントリー・解約未エントリー）
  • !2 nuworksに新規インポートして、入れた会員IDだけエントリー済みにする
  • !3 nuworksで一括解約して、入れた会員IDだけ解約エントリー済みにする
  • !4 Salesforceに進捗を反映（本番だけ）
項目何を決めるどう設定する
決済システムのURL⚙️ 設定CSVを受け取る先管理ボードのアドレスの、/admin より前の部分。はじめから入っています。
この日より前の申込は拾わない⚙️ 設定未エントリーを拾う区切り既定 2026/09/01。ふだんは変えません。決済システムで「エントリー済み」を記録しはじめる前の案件を、nuworksへもう一度入れないための区切りです（nuworksは同じエントリーを2回入れると2件になります）。
新規インポートのロボット⚙️ 設定エントリーを入れるロボット既定「暮らし安心」。手順書の値に {エントリーファイル} と書いておくと、受け取ったCSVに差し替わります。エントリーが0件の日は動かしません。
一括解約のロボット⚙️ 設定解約を入れるロボット既定「暮らし安心_解約」。手順書の値に {解約ファイル}。解約未エントリーが0件の日は動かしません（空のCSVを入れるとnuworksがエラーを出すため）。最後に「完了しました」の「はい」が出なければ、エラーとして止まり、解約エントリー済みにしません（次の回にもう一度入れます）。入れ忘れた日の解約も次の回に拾います。決済システムの管理ボードの「解約未エントリー」タブで確かめられます。
🔑 合言葉を作る ／ 作り直す⚙️ 設定決済システムを呼ぶための合言葉押すと合言葉が1回だけ画面に出ます。コピーして Vercel（決済システム）の Environment Variables に ENKAN_API_TOKEN として貼り、Redeploy します。暗号化して保存するので、どのPCからも使えます。作り直すと Vercel 側も貼り直しです。
🔎 決済システムから件数を読む—（読むだけ）いま入れる対象の件数と会員IDを出します。何も入れず、何も変えません。
🧪 お試し（インポートしない）ロボットの確かめログインして、エントリーのCSVを選ぶところまで。nuworksには入れません。
nuworksに本当に入れます（取り消せません）→ 🚀 本番入れて、エントリー済みにするチェックを入れないと押せません。時間指定の自動実行（🛡 暮らし安心のエントリー）も同じ流れです。解約をその日のうちに入れるなら、営業が終わった後（21時など）に動かします。
nuworksを見て確かめました → ✅ 入っていた ／ ↩ 入っていなかった前回の控えの片付け前回、インポートの途中で止まった・エントリー済みにできなかったときだけ出ます。nuworksにその会員IDが入っていれば「✅ 入っていた」（決済システムでエントリー済みにします）、入っていなければ「↩ 入っていなかった」（次の回にもう一度入れます）。

☁️ Salesforceへの進捗反映

決済システムの「データローダ」CSVと同じ中身を、案件（SAF案件番号＝案件ID）に入れます。付帯OP_暮らし安心（プラス→確定案件_プラス／プレミアム→確定案件_プレミアム。入っていても上書き・解約した案件も同じ）、課金開始日（暮らし安心）、解約日（暮らし安心）（空の案件は送らず、今の値を残します）。

項目何を決めるどう設定する
本番のあと、Salesforceに進捗（付帯OP・課金開始日・解約日）も入れる⚙️ 設定毎晩の本番の最後に反映するか既定ON。エントリーの結果にかかわらず、本番・時間指定の最後（④）に入れます。お試しでは入れません。
進捗反映：この日以降の申込を入れる⚙️ 設定入れる申込の期間既定 2026/08/01。この日からきょうまでの申込を毎回まとめて入れ直します（同じ値なら何も変わりません）。
Salesforceに入れます（上書きします）→ ☁️ 進捗を反映する進捗だけを今すぐ入れるチェックを入れないと押せません。nuworksには何もしません。
二重に入れないしくみ。インポートに進む前に「これから入れる会員ID」を控え、エントリー済みにできたら消します。控えが残っているあいだは、本番も時間指定も入れずに止まります（Slackで知らせます）。入ったかどうかは、人がnuworksを見て上のボタンで決めてください。

毎日（営業後）、ブルービーンの録音のうちきょうの分と前の日の分を落として、Googleドライブの日付フォルダ（2026年/9月/30 など）に入れます。翌月1日は、毎日取っておいた先月の1日ずつのファイルを1本の月まとめ（voicedata_2026-09-01_2026-09-30.tar）にして「2026年/元データZIP」に入れ、全部そろったときだけブルービーンから一括削除します。ブルービーンから1か月まとめて落とすと途中で切れる（切れると ダウンロード.htm や .crdownload が残る）ので、1か月まとめては落としません。

⚙️ 設定最初に1回だけ

項目何を決めるどう設定する
保存先のGoogleドライブのフォルダ（URL）録音を入れる先「01_通録」フォルダのURL。この下の「2026年」「元データZIP」「9月」「01」などを使います（無ければ作ります）。
ログインに使うロボットブルービーンに入る方法既定は 共通_ブルービーン投入。そのロボットのログインの手順とパスワードだけを使います。一括削除のパスワード欄にも、そのロボットに保存したパスワードを入れます（ブラウザが覚えている値は使いません）。
この月から扱う（YYYY-MM）時間指定で動かす最初の月既定は 2026-09。これより前の月は動かしません。
🔑 ドライブの許可を出すアプリがDriveに入れてよいか「01_通録」にファイルを入れられるアカウントで、1回だけ押します。許可は暗号化して保存し、自動実行用のPCでも使います。

📥 毎日：きょうの分を入れる

項目何を決めるどう設定する
📥 きょうの分を入れるきょうの分を日付フォルダへふだんは時間指定で毎日動くので、押す必要はありません。前の日の分も取り直します（営業後に落としたあとに入った録音を拾うため）。Driveに同じ名前・同じ大きさのファイルがあれば入れないので、手で入れた日があっても重なりません。

▶ 月の締め：月まとめと一括削除（翌月1日から）

項目何を決めるどう設定する
どの月？締める月ふだんは出ている月のまま。月末の日には締められません（その日の夜の録音を取り直してから消すため。翌月1日から締められます）。毎日の分が無い日（止まっていた日など）だけ、ここで落とし直します。失敗したときは、済むまで時間指定が毎日やり直します。
📤 月まとめを入れて確かめるだけ（消さない）お試し元データZIPへ入れて、日付フォルダにそろっているかを確かめます。ブルービーンからは消しません。元データZIPに手で入れた同じ名前の月まとめがあれば入れません（2本にならないように）。アプリが前に入れた月まとめは、中身が増えていれば差し替えます（古いほうはゴミ箱へ）。
🚀 月まとめを入れて、そろったら一括削除本番確認のチェックを入れないと押せません。
一括削除は取り消せません。全ファイルが日付フォルダに同じ名前・同じ大きさでそろったときだけ消します。1日でも落とせない・1件でもDriveに無いときは消さずに止まります。ブルービーンの注意書きどおり、架電業務時間外（営業後）に動かしてください。
時間指定の自動実行では「🎧 通録ダウンロード」を毎日（全曜日）の営業後に1本入れてください。毎日はきょうの分をDriveに入れ、翌月1日は前の日（月末）を取り直してから、先月の月まとめと一括削除まで行います。失敗したら、済むまで毎日やり直します。

⏰ 時間指定の自動実行

決めた時刻に、決めた業務（進捗反映・SMS送信・データローダー・オートコール投入・SFレポート更新・イレギュラー報告・エントリー前DC・地域手配・RENXA・ロボットを1回動かす）を、電源を入れっぱなしのPCで自動で動かします。人の確認が要らない業務を、人がいない時間に回すのが基本の使い方です。予定の登録はどのPCからでもできます。見回りを登録するPCは何台でもよく、動くのは「メイン」に決めた1台だけです。

確認を飛ばす設定はありません。 送信・投入は取り消せないので、各業務の設定にある「どこまで自動で行くか」（SMS送信の「一括送信まで自動で行う」、データローダーの「④の投入まで自動で行う」、オートコール投入の「投入まで自動で行う」など）にそのまま従います。OFFの工程では手前で止まり、Slackで知らせます（送信・投入はしません）。止まる場所を変えたいときは、その業務の設定画面で変えてください。

⏰ 朝の自動実行とSlack

「⏰ 時間指定の自動実行」で業務に 📦 地域手配 を選ぶと、その日の続きから進めます。朝と夕方など1日2回入れるのがおすすめです。

  • 1回目（朝）：3枚を更新 → 抜けチェック → 抜けが0件で「FAXまで自動」がONならFAXを送る（Driveにも保存）→ 送った分の手配日を入れる → 電話・WEBの残りをSlackで名指し。
  • 2回目（夕方）：まず、昼のあいだに済んだ案件（電話で「対応した」にした分など）の手配日を入れてから3枚を更新します。朝FAXした分はレポートから消え、朝の電話の残りと新しい案件が出てくるので、まとめて手配してください。新しいFAXの分は、朝と同じように送ります。
手配日を入れる前に更新はしません。入れないまま更新すると、その案件がレポートから外れて手配日の入れ忘れになったり、FAXのシートに前のお客様が残って二重に送ることになります。手配日を入れられなかったとき（「自動で入れる」がOFF・Salesforceでつまずいた）は、更新しないで止まり、Slackで知らせます。

🚨 利用開始が今日・明日なのに済んでいない案件は、Slackと画面のいちばん上に 🚨 で出します。済んだのに手配日を入れていない案件は、日が変わっても消えずに残ります。

抜けが1件でもあれば、FAXの前で止めて、案件IDと理由をSlackに出します。

項目何を決めるどう設定する
SlackのWebhook URL通知を送るチャンネルSlack の「Incoming Webhook」で作った https://hooks.slack.com/… を貼って「💾 保存」。保存すると暗号化してSupabaseに入り、画面には出しません。保存したとき、そのチャンネルに「登録しました」と1通届きます。
📨 テストで1通送る届くかの確かめ保存した送り先に、テストの通知を1通送ります。
保存した送り先を消します（どのPCからも通知しなくなります）「🗑 送り先を消す」を押してよいかの確認チェックを入れると押せます。消すと、全PCで通知が止まります。

📣 ほかの送り先（グループ）

時間指定の自動実行で、いつもの送り先に加えて別のチャンネルにも知らせたいときに使います。Slack の Webhook は1本につき1チャンネルなので、送りたいチャンネル用に Webhook を作って、名前をつけて保存します。どの予定で送るか・完了と失敗のどちらを送るかは「⏰ 時間指定の自動実行」の予定ごとに選びます。

項目何を決めるどう設定する
送り先の名前予定の画面で選ぶときの呼び名例：TSグループ。同じ名前で保存すると、URLを差し替えます。
そのチャンネルのWebhook URL送る先のチャンネルそのチャンネル用に作った https://hooks.slack.com/… を貼って「＋ 足す」。いつもの送り先と同じく暗号化して全PCで共有し、画面には出しません。保存したとき、そのチャンネルに「登録しました」と1通届きます。一覧の「📨 テスト」で1通送れ、「🗑 消す」で消せます（消した送り先を選んでいた予定は、そのグループには送らなくなります）。
「保存されていますが、このPCでは読めません」と出たとき。そのPCの ENKAN_SECRET_KEY が、保存したPCと違います（パスワードの保存と同じ鍵です）。動いているPCの secrets.toml の鍵をそのままコピーしてください。そのPCの secrets.toml に SLACK_WEBHOOK_URL が書いてあれば、そちらが優先されます。
